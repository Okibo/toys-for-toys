# Analytics and Data Usage Details for Toy-for-Toy

**Version: 1.0**
**Effective Date: January 1, 2025**
**Last Modified: January 1, 2025**

## 1. Introduction

This document provides detailed information about how Toy-for-Toy collects, uses, stores, and protects analytics data. Analytics helps us understand how users interact with the Platform and improve the experience. **All analytics collection is optional and requires your explicit opt-in consent.**

This document supplements our main Privacy Policy and should be read in conjunction with it.

## 2. What is Behavioral Analytics?

Behavioral analytics refers to the collection and analysis of how users interact with the Platform:
- Pages and features visited
- Time spent on each section
- Search queries and filters used
- Buttons clicked and features used
- Errors encountered
- Device and browser information
- Geographic location (country/city level only, never precise)

## 3. Opt-In and Consent

### 3.1 Explicit Consent Required

Behavioral analytics is completely optional. We require:
- **Explicit, informed consent** before any analytics collection
- **Clear disclosure** of what is collected and how it is used
- **Easy withdrawal** mechanism at any time
- **No pre-ticked boxes** or default opt-in

### 3.2 When Consent Is Requested

You will be asked to opt-in:
- During account creation (optional step, can skip)
- In Settings → Privacy → Analytics
- Via email campaigns (if you opt-in to communications)

### 3.3 How to Manage Consent

In Settings → Privacy → Analytics:
- **Turn On:** Check box to enable behavioral analytics
- **Turn Off:** Uncheck box to disable analytics
- **Withdraw:** Click "Withdraw Analytics Consent" button
- **Verify Status:** See your current analytics preference

Consent changes take effect immediately upon submission.

## 4. What Data We Collect

### 4.1 User Behavior Data

When analytics is enabled, we collect:

**App/Website Usage:**
- Page URLs visited (not including URL parameters that might contain sensitive data)
- Time spent on each page/screen
- Entry and exit points
- Navigation patterns between pages
- Features used and frequency
- Search queries and filter selections
- Sort preferences applied

**Interaction Data:**
- Buttons clicked
- Forms submitted
- Tabs or sections expanded/collapsed
- Features tried but not completed
- Content shared or saved
- Chat initiations (not message content)

**Session Information:**
- Session duration
- Session ID (random, not linked to account initially)
- Timestamp of actions
- Sequence of actions

**Error and Performance:**
- JavaScript errors encountered
- Page load times
- Feature failure reports
- Browser console errors (without sensitive data)
- Crash reports (if applicable)

### 4.2 Device and Environment Data

We collect:
- Device type (mobile, tablet, desktop)
- Operating system and version
- Browser type and version
- Screen resolution
- Network type (WiFi, cellular, etc.)
- Geographic location (country and city only)
- Device language
- Timezone

We do NOT collect:
- Exact GPS coordinates
- IMEI or serial numbers
- Unique device identifiers
- SIM card information
- Personal health information
- Biometric data

### 4.3 No Personally Identifiable Information

Our analytics system is designed to NOT collect:
- Email addresses or usernames
- Names or contact information
- Financial or payment information
- Credit card details
- Social Security numbers or IDs
- Precise location data
- Chat message content
- Toy descriptions or photos
- Any data that could identify a specific person

### 4.4 Data Anonymization

All analytics data is immediately anonymized:
- User IDs are replaced with random session tokens
- IP addresses are not stored in analytics
- Data is aggregated to prevent re-identification
- No cookies linking analytics to user identity
- No cross-device tracking

## 5. How We Use Analytics Data

### 5.1 Service Improvement

We use analytics to:
- **Identify Features:** Understand which features are used most
- **Fix Problems:** Find and fix bugs affecting many users
- **Improve UX:** Redesign confusing or problematic flows
- **Optimize Performance:** Speed up slow pages
- **Add Features:** Develop new features users want
- **Better Matching:** Improve toy matching algorithm
- **Simplify:** Remove unused or confusing features

### 5.2 User Research and Insights

We use analytics to:
- **Understand Patterns:** How users discover and exchange toys
- **Analyze Workflows:** Common sequences of actions
- **Identify Friction:** Where users abandon actions
- **Measure Success:** Track adoption of new features
- **Compare Versions:** A/B test new designs

### 5.3 What We Do NOT Use Analytics For

We explicitly do NOT use analytics for:
- **Targeted Advertising:** No behavioral targeting ads
- **Price Discrimination:** No personalized pricing
- **User Profiling:** No creation of user segments for control
- **Restricting Service:** No denial of service based on behavior
- **Credit Decisions:** No automated decisions affecting you
- **Surveillance:** No tracking across websites or apps
- **Sale of Data:** No selling or sharing of analytics data

### 5.4 Aggregate-Only Reporting

All analytics reports are:
- **Aggregated:** Showing trends, not individual users
- **Anonymized:** No way to identify specific individuals
- **Segmented:** By cohort (age group, device type, etc.) never individuals
- **Time-Bound:** Showing patterns over periods
- **Statistical:** Using averages and percentages

### 5.5 Data Usage Examples

Examples of how we use analytics (in aggregated form):
- "60% of users who view the matching screen complete an exchange"
- "Users spend an average of 3 minutes viewing toy listings"
- "The most common search filter is by age group"
- "iOS users take 2 seconds longer to rate exchanges than Android users"
- "30% of users enable behavioral analytics"

Examples we do NOT do:
- "User [ID] spends too long on toy listings"
- "User [ID] canceled exchanges 3 times"
- "User [ID] searched for X and then bought Y"
- Tracking you across other websites
- Building a psychological profile of you

## 6. Data Retention and Deletion

### 6.1 Retention Timeline

| Data Type | Retention | Reason |
|---|---|---|
| Raw analytics events | 90 days | GDPR data minimization |
| Aggregated analytics | Indefinite | No personal data; trends needed for improvement |
| Session data | 30 days | Performance optimization |
| Error logs | 90 days | Bug fixing and improvement |
| Device analytics | 90 days | Performance monitoring |

### 6.2 Automatic Deletion

Raw analytics data is automatically deleted after 90 days. However:
- Aggregated, anonymized data is kept indefinitely
- This data cannot identify you and is purely statistical
- You cannot withdraw consent retroactively for data already aggregated
- After your consent withdrawal, only new raw data is deleted (old aggregates remain)

### 6.3 Withdrawal of Consent

When you withdraw analytics consent:
- **Immediately:** No new analytics data collected
- **90 Days:** Raw event data deleted (if not yet deleted)
- **Indefinite:** Aggregated data may remain (cannot identify you)
- **Not Retroactive:** You cannot delete data already aggregated
- **Confirmation:** You receive confirmation that withdrawal is effective

### 6.4 Account Deletion

When you delete your account:
- All analytics data linked to your account is deleted
- Aggregated analytics may still contain historical data
- No way to identify data was from your account
- Historical trends are preserved without identifying you

## 7. Data Security and Privacy

### 7.1 Access and Storage

Analytics data is:
- **Encrypted in transit:** TLS 1.2+ encryption
- **Encrypted at rest:** Sensitive data encrypted in database
- **Access restricted:** Only analytics team has access
- **Logged:** All access to analytics data is logged
- **Compartmentalized:** Kept separate from personal data

### 7.2 Aggregation Process

To prevent re-identification:
- Individual events removed after aggregation
- Minimum group sizes enforced (no segments with <10 people)
- Demographic breakdowns use broad categories
- Geographic data limited to country/city (no postal codes)
- Time-based aggregation prevents identifying patterns

### 7.3 No Retention of Identifiers

We specifically do NOT retain:
- Your account ID in analytics records
- Your email address or name in analytics
- Any field that could identify you personally
- Linking data between analytics and accounts
- Session IDs that persist across sessions

### 8.2 No Other Third-Party Tracking

We do NOT use:
- Facebook Pixel for tracking
- LinkedIn Insight Tag
- Amplitude or Mixpanel
- Segment or other CDP
- Any other third-party analytics (unless explicitly disclosed)

## 11. Do Not Track (DNT)

### 11.1 Respect for DNT Signals

If your browser sends a "Do Not Track" signal:
- We recognize the DNT header
- We disable optional tracking cookies
- We disable behavioral analytics
- Essential service cookies are not affected (required for functionality)

### 11.2 Enabling DNT

To enable Do Not Track:
- Chrome: Settings → Privacy → Send "Do Not Track" requests
- Firefox: Options → Privacy → Send "Do Not Track" signals
- Safari: Preferences → Privacy → Request not to be tracked
- Edge: Settings → Privacy → Send "Do Not Track" requests

## 15. Definitions

**Behavioral Analytics:** Collection and analysis of how users interact with the Platform (pages visited, features used, etc.)

**Anonymization:** Process of removing all identifying information so data cannot be linked to individuals

**Aggregation:** Combining data from multiple individuals into statistical summaries

**Consent:** Freely given, specific, informed, and unambiguous indication of willingness to process data

**Data Subject:** The individual whose personal data is being processed

**PII (Personally Identifiable Information):** Data that can be used to identify an individual (name, email, ID number, etc.)

**Session:** A period of interaction with the Platform (login to logout)
