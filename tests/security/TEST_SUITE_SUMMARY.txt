KEY SECURITY PRINCIPLES TESTED
================================================================================

1. Deny by Default
   ✓ Access is denied unless explicitly allowed
   ✓ Tests verify denials for unauthorized operations
   ✓ Tests verify allows for authorized operations

2. Data Isolation
   ✓ Each user's data is strictly isolated
   ✓ Cross-user queries return no data
   ✓ RLS enforced at database layer

3. Immutable Audit Trails
   ✓ Consent records cannot be modified/deleted
   ✓ Transaction logs cannot be modified
   ✓ Only system can change via triggers

4. System-Managed Data
   ✓ Ticket balances managed only by system
   ✓ Users cannot directly modify balance
   ✓ Only transactions and triggers can change

5. RLS Cascading
   ✓ Parent table RLS filters child table access
   ✓ Toy images filtered through toy ownership
   ✓ Exchange data filtered through relationships

6. SQL Injection Protection
   ✓ RLS enforces security before execution
   ✓ Special characters cannot bypass RLS
   ✓ OR true conditions are prevented

7. Service Role Bypass
   ✓ Backend services can bypass RLS
   ✓ Using service role key for admin operations
   ✓ Separated from user-level access
